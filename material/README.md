## 2. 权威层级与主副本

1. **A 级：设定与系统依据**  
   `Steins Gate 0 Official Document Amadeus' Script.pdf` 是本目录的内容主副本；逐页 PNG 只是便于检索的工作副本。若 PNG 文件号、扫描页码和理解发生冲突，以 PDF 中的完整上下文为准。
2. **B 级：系列视觉依据**  
   三套 STEINS;GATE 插画/Visual Works 用于人物外观、构图、色彩和气氛分析，不用单张插画反推剧情事实。
3. **C 级：作者风格依据**  
   `BLK` 含非 STEINS;GATE 内容，只能提炼抽象视觉语言，不能作为人物、时间线或道具的设定来源。

原始扫描件保持只读。裁切、调色、抠图、压缩、标注和项目用衍生稿应另存到 `design-reference/derived/`，不得覆盖 `material/` 中的源文件。

## 4. 从素材得到的产品结论

1. **当前项目不能只是一块聊天窗口。** 官方资料把剧情路线、消息档案、世界线矩阵、地图、组织关系和 Amadeus 会话放在同一套信息体系内；项目需要一个可检索、可解锁的“档案终端”。
2. **世界线应是事件数据，不只是一个小数和换肤状态。** 至少要记录触发原因、发生时间、前后世界线、影响的记忆键和可见资料。
3. **Amadeus 的关系变化要由进度驱动。** `230.png` 显示会话存在明确的可触发阶段；后续应把关系阶段、称呼、表情和可访问记忆做成确定性状态，由模型负责措辞而不是决定事实。
4. **RINE/D-Mail 应先做档案和规则，再做自由输入。** 先实现只读消息档案、固定分支和可回放结果，能够验证数据模型后再开放用户生成内容。
5. **角色表现不能只有“说话/不说话”。** 红莉栖资料包含多种表情、正背面与姿态；前端至少需要受限的 `neutral / analytical / annoyed / concerned / soft / surprised` 状态，并与文字、语音和动画共享同一状态源。
6. **地点和组织是任务系统的骨架。** 地图页与组织页可以转化为原创的地点卡、线索卡和访问权限，而不是直接展示扫描图。

## 5. 素材使用流程

每次从本目录取材时，按以下顺序记录：

1. 先写功能问题，例如“世界线日志要展示哪些字段”，再查页面，不做无目标的批量搬运。
2. 记录 `source_path`、PNG 文件号、印刷页码（可见时）、用途和结论摘要。
3. 标记 `rights_status`：`reference-only`、`private-prototype` 或 `cleared-for-public`。默认一律为 `reference-only`。
4. 只提炼信息结构、状态关系、配色/构图规律和原创需求；不要大段转录、翻译或复制原作台词。
5. 所有衍生图放入 `design-reference/derived/`，并为每个文件保留来源记录；真正上站的资源只允许进入 `public/` 前通过权利检查。
6. 功能完成后，把实际实现和来源页回填到项目规划的验收记录中。

建议后续新增一个衍生素材清单，字段至少包括：

```csv
asset_id,source_path,source_page,intended_use,rights_status,derivative_path,reviewer,reviewed_at,notes
```

- 未取得许可前，不把 PDF、扫描页、原作 Logo、RINE Stamp、角色立绘或其高相似裁切图放入 `public/`、发行包或公网部署。
- 未确认仓库可见性、授权和大文件存储方案前，不应提交这些原始素材；即使使用 Git LFS，也不能替代版权许可。
- 面向公网的界面、图标、地点卡和文案应重新设计，并在视觉上避免让用户误认为是官方产品。
